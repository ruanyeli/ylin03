IQuest-Q1: Learning to Build the Next Model IQuest-Q1：让模型参与自身的改进

IQuest-Q1 is an open-source model for coding and tool use. Through recursive self-improvement, each version helps diagnose its limits and develop the next, with researchers guiding experiments and reviewing results. IQuest-Q1 是面向编程与工具使用的开源基础模型。它参与自身的研发：发现短板、执行实验，将有效改进带入下一轮迭代；研究人员把握方向并审核结果。

Overview概览

IQuest-Q1 is trained to work through tasks: gather context, use tools, check results, and recover from errors. Its capabilities span information work and repository-level software development. IQuest-Q1 围绕完整的任务过程训练：理解上下文、调用工具、验证结果，并在出错后调整。能力覆盖信息处理、办公协作和代码开发。

01

Models that contribute to their own development模型参与自身研发

Each iteration improves both the model and the tools used to develop it. Researchers review the results before carrying changes into the next round. 每轮迭代同时改进模型和研发工具。经过研究人员评审后，有效的模型更新、训练数据和实验流程会保留到下一轮。

02

Coding and general-purpose tool use兼顾编程与通用任务

IQuest-Q1 combines code reasoning and repository-level development with information gathering and tool use. Its architecture is designed to support these tasks efficiently. 从理解代码、修改仓库，到查找信息、调用工具，IQuest-Q1 将这些能力融于同一模型，并通过架构设计降低计算开销。

03

Training across agent frameworks在多种智能体框架中训练

A shared policy learns in Codex, Claude Code, and Terminus, using each framework’s own tools, context management, and interaction flow. 同一模型在 Codex、Claude Code 和 Terminus 等框架中学习，直接使用各自的工具接口、上下文管理方式和交互流程。

04

Bringing specialist capabilities together整合不同领域的能力

Execution-verified tasks, supervised fine-tuning, specialized reinforcement learning, and multi-teacher distillation bring coding, reasoning, and general-agent skills into one model. 用实际执行来验证合成任务，结合监督微调、领域强化学习和多教师蒸馏，将编程、推理与通用智能体能力整合到一个模型中。

Recursive Self-Improvement, Guided by Researchers研究人员指导下的递归自我改进

Each RSI iteration improves both the model and the research process. Accepted model versions, training data, and tools become the starting point for the next round. 每轮 RSI 同时改进模型与研发流程。通过评审的模型版本、训练数据和工具，成为下一轮工作的起点。

Two connected cycles of improvement模型能力与研发方法，一同改进

Capability flywheel能力飞轮

The agent improves the model and training data to raise performance or reduce inference cost. Updates are evaluated under a fixed protocol before adoption. 智能体调整模型与训练数据，提高任务表现或降低推理成本。更新经过统一评测与人工评审后，再用于下一轮。

Development flywheel研发飞轮

The agent improves the research tools and workflows, turning lessons from experiments into reusable procedures. 智能体改进研发工具与流程，将实验中验证有效的做法整理为可复用步骤。

Training Pipeline训练流程

Pre-training builds broad knowledge; mid-training adds reasoning, agent trajectories, and context extension to 512K. Post-training brings specialized capabilities into one model. 预训练建立基础知识，中期训练加入推理与智能体轨迹，并将上下文扩展至 512K；后训练整合各领域能力。

Post-training后训练

Large-scale, diverse task synthesis大规模多样化任务合成

Tasks cover tool use, coding, and reasoning. Reference solutions, code execution, tests, and proofs verify the synthesized data. 合成任务覆盖工具使用、编程与推理，通过参考解、代码执行、测试或证明验证数据质量。

Learning through task execution在任务执行中进行强化学习

A shared policy learns across agent frameworks. Failures are checked so infrastructure faults do not become misleading training feedback. 同一策略在多种智能体框架中学习。训练前区分模型错误与基础设施故障，避免无效反馈干扰学习。

Multi-teacher on-policy distillation (MOPD)多教师在线策略蒸馏（MOPD）

Multi-teacher on-policy distillation combines Claude Code, multi-harness, long-horizon, and general-purpose specialists into one model. 通过多教师在线策略蒸馏（MOPD），将 Claude Code、多框架适配、长程任务与通用能力专家整合到同一模型。

Post-training infrastructure后训练基础设施

A shared runtime collects trajectories across frameworks, keeps tokens consistent between rollout and training, and supports asynchronous multi-teacher distillation. 统一运行环境汇集不同框架的轨迹，保证采样与训练的 token 一致，并支持异步多教师蒸馏。

Case 1 · An extra space that broke multi-turn training案例 1 · 一个空格，让多轮训练只剩最后一轮

Claude Code CLI

Working in Claude Code, IQuest-Q1 traced an unusual reward curve to an extra space in decoded text that left only the final turn in the training loss. IQuest-Q1 在 Claude Code 中排查奖励异常，发现解码时多出的空格导致训练只覆盖最后一轮回答。

Locate the issue定位问题→ Fix the bug修复 Bug→ Reward improves效果提升
Cause原因
Extra spaces inserted during decoding broke prefix matching. Earlier turns remained in context but dropped out of the training loss.解码器额外插入的空格破坏了前缀匹配。前几轮回答仍在上下文中，却不再参与损失计算。
Fix修复
Disable injected separator spaces while preserving generated whitespace, and keep streamed and stored text consistent.关闭额外分隔空格，保留模型生成的空白字符，并确保流式文本与存储轨迹一致。
Result结果
Multi-turn training was restored. Mean reward rose from 0.704 to 0.769, reaching 0.799 later in training.多轮训练恢复，奖励均值从 0.704 升至 0.769，后续达到 0.799。

Case 2 · When an environment fault looks like model failure案例 2 · 环境出了故障，模型却被判为失败

Claude Code CLI

After an environment update, previously solvable tasks began receiving low rewards. IQuest-Q1 investigated the execution and grading pipeline in Claude Code. 环境更新后，原本能完成的任务开始大量得低分。IQuest-Q1 在 Claude Code 中排查任务执行与评分流程。

Cluster failures失败聚类→ Trace the timeline时间线排查→ Repair environment & grading修复环境与评分→ Re-validate复验
Cause原因
Dependency, test-startup, and service-access faults caused some tasks to fail before the model’s patch ran. The grader counted these as model failures.依赖、测试启动与服务访问故障，使部分任务在补丁执行前就失败，并被计入模型的负奖励。
Fix修复
Repair the environment, add health checks, and exclude confirmed infrastructure faults from policy updates. Genuine model failures still receive negative reward.修复环境并增加健康检查，将确认的基础设施故障排除出策略更新；模型自身的失败仍保留负奖励。
Validation验证
Re-run the same tasks and patches to check scoring recovery. Quantitative results remain pending; restored scoring is distinct from improved model capability.用同一批任务与补丁复验评分恢复情况。量化结果待补充，评分恢复与模型能力提升分别判断。

Case 3 · A research workbench, then a fix from inside it案例 3 · 先搭研发工作台，再在台上修复失败任务

Claude Code CLI

A researcher asked IQuest-Q1 to build a workbench for inspecting research sessions—failed commands, logs, diffs, tests, and reports tied to the right code version—and then to repair a failed export from within that page. 研究人员请 IQuest-Q1 搭建一个研发工作台，用来查看研发会话中的失败命令、日志、代码改动、测试和报告，并与对应代码版本绑定；随后在工作台上发起修复一个失败的导出任务。

Build the workbench搭建工作台→ Inspect the failure查看失败记录→ Minimal fix最小修复→ Verify the artifact校验产物
Cause原因
The review-bundle export failed because some source files carried a modification time of 0 (1970), and Python’s zipfile rejects timestamps before 1980.部分源文件的修改时间为 0（1970 年），而 Python 的 zipfile 不接受 1980 年之前的时间戳，导致评审包导出失败。
Fix修复
A minimal change—strict_timestamps=False on the archive—plus a regression test with mixed modern and pre-1980 timestamps. Project data and its timestamps were left untouched.只做最小改动：为归档设置 strict_timestamps=False，并补充一条混合新旧时间戳的回归测试；项目数据及其时间戳保持不变。
Verification验证
Workbench and project tests pass. An integrity report compares the archive against the source files and confirms every file is present and byte-identical.工作台与项目测试全部通过；完整性报告逐一比对归档与源文件，确认所有文件齐全且逐字节一致。

15Scientific visualization科学可视化
